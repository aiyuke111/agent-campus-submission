# 05 复盘

## 最难的三件事

1. **确认边界**：用户要求 18:00、时段被占，既要给出可执行方案，又不能擅自改硬性要求。  
   做法：替代时段只写入 `suggested_slot`，`hard_requirement_modified=false`，待确认项里明确写"原要求未被修改"。

2. **防重复**：相同请求重复提交只能有一份草稿。  
   做法：幂等键覆盖"素材 + 日期 + 时段 + 规则版本"，命中即返回原 `draft_id`，`duplicate=true`，不新增记录。

3. **失败真实性**：保存失败时不能把流程"跑完"当成成功。  
   做法：`save_draft` 失败抛 `ToolError`，Agent 转为 `SAVE_FAILED` 并置 `draft.saved=false`；不重试、不补写。

## 学到什么

- 把"模型决策"与"业务确定性"分层：工具与规则可测试，模型只负责选下一步，测试才稳定；
- Trace 先行：先定字段（参数、摘要、下一步、依据），实现与验收都围绕它；
- 验收点驱动测试：6 个验收点各对应至少一条集成测试，避免"跑通即完成"的错觉。

## 不足与下一步

- 真实模型接入：需要工具调用协议、错误重试与超时控制，当前仅保留适配层；
- 存储：文件存储改为带事务的数据库，增加并发写锁与草稿版本；
- 规则：抽象为可配置 DSL，支持按业务线扩展；
- 观测：Trace 落库与看板，统计阻断原因、替代时段采纳率、重复提交率。

## 评审反馈后的修复（第二轮）

外部评审用反例指出了几处真实缺陷，已修复并补测试：

1. **结束结论可虚报**：模型直接 finish "已保存" 时，Agent 只信模型。修复为用真实工具状态复核 `finish`，不一致强制 `ERROR`。
2. **跳过审核直接保存**：守卫只检查动作名。修复为增加前置条件检查（素材/规则/时段/建议时段/参数一致性）。
3. **草稿之间会撞时段**：查询只看静态排期。修复为查询与保存都纳入已保存草稿，并在文件锁内二次校验。
4. **真实写盘失败会崩溃且污染内存**：改为原子写 + `SAVE_FAILED`，写成功后才提交内存状态。
5. **非法输入崩溃/误判**：日期、时间、`hard` 类型统一校验，返回 `NEEDS_INPUT`。
6. **模型输出异常无兜底**：决策、执行、CLI 三层转结构化 `ERROR`。
7. **幂等键缺请求意图**：键加入 `requested_time` 与 `hard`。
8. **配置漂移**：`search_days` 改为从数据文件注入策略。

最大的收获：**"模型可以决定下一步"不等于"模型可以决定事实"**。业务事实（是否保存、是否冲突、是否高风险）必须由工具状态复核，模型只负责选择动作。
